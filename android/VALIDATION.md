## 真实使用仍需确认的边界

1. **网络可达性**：同一路由器下的访客网络、设备隔离、VPN、Windows 公用网络配置可能阻断连接。电脑 IP 改变后需要重新扫码；此版本没有后台自动发现地址。Wi-Fi 无互联网时，部分手机会自动切换移动数据，需要在系统中保持连接该 Wi-Fi。引导不能绕过路由器隔离或代替用户授予系统权限。
2. **锁屏与内存回收**：短时 Home 切换已验证；厂商省电策略、长时间锁屏、全应用进程被杀尚未实测。服务端任务是否继续取决于电脑/服务器是否运行；手机内存中的草稿和未完成文件传输不保证恢复。
3. **实际输入与表格性能**：中文输入法候选栏、折叠屏、多窗口、低内存手机上的 Univer 大表格编辑、云盘文件提供程序仍需目标设备检查。上传遵循后端限制，客户端保存上限 256 MB；未进行接近上限的内存压力测试。
4. **模型与第三方授权**：未使用真实账户或产生模型调用。需要回调电脑 localhost 的第三方授权不能假定在手机浏览器中可完成；优先在电脑配置，支持的设备码流程另行真机验收。
5. **版本与发行**：需要较新 WebView；缺少必要能力会提示更新。扫码页当前保持竖屏。预览包为调试签名，正式发行需固定签名和发布流程；此轮未更新已安装的 Windows 桌面程序。
6. **新系统权限**：当前 targetSdk 为 35。按 Android 官方规则，targetSdk ≤36 的应用仍通过 INTERNET 隐式获得局域网访问；升级至 targetSdk 37 后必须增加 ACCESS_LOCAL_NETWORK 的请求及拒绝恢复流程，不能只改版本数字。[Android 局域网权限说明](https://developer.android.com/privacy-and-security/local-network-permission)

实现参考：[Chrome Clipboard API](https://web.dev/articles/async-clipboard?hl=en)、[Android WebView 进程终止处理](https://developer.android.com/develop/ui/views/layout/webapps/handle-termination?authuser=0)。

## 模拟器实际覆盖范围

1. 在真实 WebView 的页面脚本执行前注入运行配置及令牌；网站试图注入 loopback 后端地址时，客户端仍使用已选网站的同源 API。真实 HTTP 请求携带认证成功。
2. 通过原生消息通道分块传输 110,000 字节二进制数据，调用 Android 创建文档协议，经 ContentResolver 写入 MediaStore，再逐字节检查结果。
3. 通过实际触摸触发 Web 文件输入控件，调用 Android 打开文档协议，将 `content://` 文件返回 WebView，验证中文内容一致。

文档选择协议的返回结果由测试提供，底层 URI 读写和 WebView 执行使用真实 Android 实现。曾发现并修正测试的 MIME 过滤、用户激活及异步写入等待问题；未绕过 WebView 的用户激活要求。
